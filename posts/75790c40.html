利用Page CMS实现可以随时随地发送的hexo说说

发表于2026-09-23|更新于2026-09-23|网站搭建
|浏览量:

前言

平时写博客往往要先打开电脑，创建 Markdown 文件，写完再发布。但有些内容其实不需要写成文章：几句想法、一张照片，或者一次折腾的小记录，都更适合发成“说说”。

我希望这个功能满足几个条件：

  • 手机也能发布文字和图片。
  • 自动记录发布时间。
  • 图片使用已有的外部图床。
  • 每条说说可以独立评论。
  • 尽量沿用现有 Hexo 和 GitHub Pages，不增加服务器维护工作。

最终采用的方案是：

Pages CMS 编辑内容，GitHub 保存数据并自动部署，Hexo 展示说说，图床提供图片，Twikoo 保存评论。

从 Memos 到静态发布

最初考虑过搭建 Memos。它有现成的登录、图文编辑和时间线功能，手机发布也方便，但需要额外部署后台和保存数据。

后来发现，手机编辑并不一定需要给博客增加一个运行中的后台。只要能在手机上修改仓库里的内容，再交给 GitHub Actions 自动构建，同样可以完成发布。

因此，我选择了 Pages CMS。它提供网页编辑界面，保存内容时会提交到 GitHub 仓库，适合接入现有的静态博客。

这种方式需要等待构建完成后才能看到更新，不过不需要自己维护新的服务。

这篇文章记录的是当前博客中的实际实现，环境为 Hexo 8.1.1、Butterfly 5.5.4 和 Node.js 22。模板使用了 Butterfly 的 url_for、safeJSON、主题颜色变量以及已有的 Fancybox 配置，不能直接当作通用 HTML 放到其他主题里运行。

用 Pages CMS 在手机上编辑

仓库根目录新增了 .pages.yml，用它定义编辑表单，并指向说说的数据文件。

表单包括：

  • 发布时间：新建时默认当前时间。
  • 正文：多行文本输入。
  • 图片：可以增删的图片链接和说明列表。
  • 固定标识：自动生成 UUID，隐藏在编辑表单中。

手机登录 Pages CMS 后，选择博客源码仓库和 main 分支，就能通过表单维护说说，不需要手动编辑 JSON。

这里要选择的是保存 Hexo 源码的仓库，而不是部署生成页面的 GitHub Pages 仓库。

这里选择 type: file 和 list: true，让整个 JSON 文件成为一个可以增删条目的列表。images 又是一个对象列表，所以每条说说都能添加多张图片。

id 使用 UUID 字段，并关闭编辑和重新生成入口。时间字段使用带偏移量的格式，例如 2026-09-23T18:30:00+08:00，避免构建机器和手机时区不同造成显示偏差。

配置提交后，在 Pages CMS 登录 GitHub，授权博客源码仓库，再选择对应分支，就可以加载这份表单。字段配置参考 Pages CMS 官方文档。

图片继续使用外部图床

考虑到 GitHub 图片的访问速度，我没有启用 Pages CMS 的仓库媒体上传功能。

实际操作是：

  1. 在手机上登录图床并上传照片。
  2. 复制图片的 HTTPS 直链。
  3. 将直链填入说说的图片列表。
  4. 按需填写图片说明。

这样，仓库里只保存文字和图片地址，访客浏览时直接从图床加载图片，也不需要把图床密钥放进博客配置。

Hexo 如何生成页面

博客使用 Butterfly 主题，它本身就带有说说模板。这次保留了原模板，并为 Pages CMS 的数据新增了一套展示模板。

主要文件分工如下：

文件 作用
.pages.yml 定义手机编辑表单
source/_data/shuoshuo.json 保存说说数据
lib/shuoshuo.cjs 校验、整理数据并转换时间
scripts/shuoshuo.js 注册 Hexo 模板辅助函数
source/shuoshuo/index.md 定义说说页面
shuoshuo-public.pug 生成图文卡片
source/css/shuoshuo.css 控制布局和移动端样式

生成页面前，会检查日期、固定标识、图片地址，以及是否存在空白说说。有效数据统一转换为北京时间，并按发布时间倒序排列。

页面的展示方式也做了适配：

  • 单张图片保持原始比例。
  • 多张图片使用网格排列，手机上显示两列。
  • 点击图片可以放大查看。
  • 超过八条时，提供“加载更多”按钮。
  • 浅色和深色模式沿用主题配色。

“加载更多”是在已经生成的页面中逐批显示内容，不会再请求一个说说后台。

给每条说说添加独立评论

博客原本已经使用 Twikoo，因此说说直接复用了现有评论服务。

这里最关键的问题是：怎样让评论一直对应同一条说说？

如果用列表下标区分，新增或排序后，下标就会改变；如果用正文或发布时间区分，编辑内容或时间也可能改变评论归属。

所以，每条说说增加了一个保存到数据文件中的固定 id。Twikoo 使用的评论路径类似：

只要这个标识不变，即使修改正文、图片、时间或者排序，评论仍属于原来的那条说说。已有记录也补上了标识，重复或缺少标识会在校验时被发现。

每张卡片下方有一个“评论”按钮，点击后才加载评论区。考虑到 Twikoo 的全局元素标识，同一时间只挂载一个评论区，切换时使用对应说说的路径重新初始化。

同时处理了快速点击、展开收起和加载失败后的重试。评论审核、回复等操作，继续使用原来的 Twikoo 管理后台。
